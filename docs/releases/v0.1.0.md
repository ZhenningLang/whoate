# whoate 0.1.0 — first release

See which agent session, tmux pane or app is eating your Mac's memory, and let
your coding agent ask too.

## Install

Apple Silicon, macOS 14 (Sonoma) or later.

```sh
brew install zhenninglang/tap/whoate
```

The menu bar app:

```sh
brew install --cask zhenninglang/tap/whoate
```

The app carries its own copy of the CLI. To put it on your PATH without the
formula, open whoate Settings → Command Line → Install.

## First launch of the app

whoate.app is ad-hoc signed and **not notarized**, so macOS blocks the first
launch. Open it once and click **Done**, then go to **System Settings → Privacy &
Security** (系统设置 → 隐私与安全性) and click **Open Anyway** (「仍要打开」).
Or, in Terminal:

```sh
xattr -d com.apple.quarantine /Applications/whoate.app
```

## What's in it

- Memory and CPU grouped by owner: coding-agent session, tmux pane, app, or the
  orphan a closed terminal left behind.
- Per-software explanations for coding agents and their MCP servers, Chromium
  browsers, WebKit, Docker and IDEs, backed by a knowledge base where every entry
  cites its source.
- A CLI for coding agents: `whoate top --json`, `whoate why <pid>`,
  `whoate agent-guide`. Structured `whoate/v1` JSON and exit codes, zero tokens.
- A menu bar app with a main window and a settings window, in English and Chinese.

The full list is in [CHANGELOG.md](https://github.com/ZhenningLang/whoate/blob/main/CHANGELOG.md).

## Known limitations

- Apple Silicon only; macOS 14 or later.
- The app is not notarized (see above).
- Knowledge-base advice appears only when its trigger matches what runs on your
  machine; on a quiet machine you may see none for some software.

## Privacy

whoate reads local process and session information only. No telemetry: it
collects nothing, does not use the network, and calls no model.
