## 1. 现在哪儿坏了、不改会怎样

今天上午一个程序占了 9.7G 内存，活动监视器只显示它叫「node」，查清它是谁花了 9 次工具调用（[U-DIAG-1|a758]）。它其实是一个前端项目的预览服务器，启动它的终端窗口已经关了，它没人管跑了近 12 小时。本机已有的内存快照报告也没把它列出来，因为报告只看「这段时间涨了多少」，而它早在报告窗口开始前就涨完了（[U-DIAG-2|7070]）。不做这个工具，下次还得让助手花几分钟和几万 token 去拼同样的线索。

### 核心概念

- **归属**：一个进程记在谁名下，人一眼认得出。例：「tmux 窗口 15 里那个 Claude 会话」「Google Chrome」「一个终端已关掉的孤儿」，同一个进程只记一次。
- **归因证据**：凭什么记在这个名下。例：「它的环境变量写着来自 pane %266，但这个 pane 已经不存在」，每条证据标「确定」或「推断」。
- **诊断**：对每个归属的一句话判断。例：「无人管理的开发服务器，建议关闭」；只有该处理的那一档才给按钮。

## 2. 要你拍的 5 件事

**一句话：** 第一版不做苹果公证，安装说明手把手教别人第一次怎么放行（[U-DEC-1|803c]）。
选项：A 不公证，免费，别人第一次打开要去系统设置里放行一次；B 办苹果开发者账号（每年 99 美元），让苹果先检查一遍软件，别人双击就能打开。
建议：第一版不做公证，有人用起来再办账号。
不表态默认：第一版不做公证。
例子：别人下载后双击，系统说「无法打开」；他去「系统设置 → 隐私与安全性」点「仍要打开」，之后就正常了。

**一句话：** 助手查别的会话时，默认看不到你在那里打的第一个问题（[U-DEC-2|c796]）。
选项：A 默认就给助手看；B 默认不给，助手在命令里专门要求才给。你自己在界面上看不受影响。
建议：默认不给助手看第一个问题。
不表态默认：默认不给助手看第一个问题。
例子：一个助手查「谁占内存」时只看到另一个会话的标题「Node 进程内存占用过高」，看不到你在那个会话里打的原话。

**一句话：** 允许助手自己用命令关程序，但命令里必须写明「确认」（[U-DEC-3|ecb3]）。
选项：A 允许，命令里写明确认才真关，这个确认是助手自己写的，不经过你；B 不允许，命令只列出要关什么，由你在界面或终端里点确认。
建议：允许助手写明确认后关程序，系统程序一律拒绝。
不表态默认：允许助手写明确认后关程序。
例子：助手发现那个占 9.7G 的预览服务器，发一条写明确认的关闭命令，内存当场释放；它若想关系统的窗口服务，命令直接拒绝。

**一句话：** 界面和命令输出跟随系统语言，中英双语（[U-DEC-4|8bac]）。
选项：A 中英双语跟随系统；B 只做英文；C 只做中文。
建议：跟随系统语言，中英双语。
不表态默认：跟随系统语言，中英双语。
例子：你的 Mac 是中文，看到「无人管理的开发服务器」；英文系统的用户看到同一条的英文版。

**一句话：** 产品介绍页用 GitHub 自带的免费网页托管（[U-DEC-5|98d4]）。
选项：A 放在 zhenninglang.github.io/whoate，公开可访问；B 只放在仓库里，看的人要下载到本地打开。
建议：用 GitHub 免费网页托管公开发布介绍页。
不表态默认：用 GitHub 免费网页托管公开发布介绍页。
例子：你把链接发到群里，别人手机上直接点开就能看。

## 3. 撤不回来的与会变的

名字 whoate 已经公开，再改要动仓库、安装命令、程序名和给助手的说明文件（[U-GATE-1|2104]）。给助手用的数据格式一旦发布，别人的脚本就会依赖它，所以只加字段不改字段，真要改就升到第 2 版并让旧版继续可用（[U-GATE-2|fd28]）。安装渠道会多一个公开仓库专门放安装公式，名字定了以后用户的安装命令就靠它（[U-GATE-3|8918]）。

会变的行为有两条。第一，这个工具能结束进程：界面和命令都先列出要关的进程、要确认，系统进程和它自己一律拒绝（[U-BEH-1|033d]）。第二，它会只读本机 Claude Code、opencode、kilo 留下的会话记录来认出会话，从不改写它们（[U-BEH-2|7953]）。

## 4. 代价、新增依赖与运维负担

新增的东西都是开源库或免费服务，没有付费项（如果第 1 件选 B 才有每年 99 美元）。

- 命令行参数解析库 clap：九个子命令的参数和帮助文本，手写不值（[U-DEP-1|b55d]）。
- JSON 序列化库 serde：给助手的数据格式全靠它（[U-DEP-2|7600]）。
- 系统调用绑定 libc：读进程内存和 CPU 的系统接口，标准库里没有（[U-DEP-3|e267]）。
- SQLite 读取库 rusqlite：读 opencode、kilo 的会话库；每秒开一个外部命令去读太慢（[U-DEP-4|a231]）。
- GitHub 的 macOS 自动测试机：别人提的改动有机器把关，公开仓库免费（[U-DEP-5|a60c]）。
- 一个新公开仓库 homebrew-tap：放安装公式，让别人一行命令安装（[U-DEP-6|b3fe]）。

运维负担：每次发版跑一个发布脚本，更新安装公式。比不做贵在哪：未评估，主要成本是开发时间。

## 5. 分几期、多久、每期拿到什么、怎么算做完

分五期，按 agent 吞吐估一共一到两天 [推断：依据是规模估计 3000 到 5000 行，没有同类项目实测]。第三期和第四期可以同时做。

第一期把数据读准：随机抽 10 个进程，读到的内存和系统 `top` 命令差不到 1%，读一遍不到 50 毫秒（[U-ACC-1|a19b]）。第二期把「是谁」认准：用今天这台机器录下的真实数据回放，预览服务器被认成孤儿、Claude 会话认出名字和第一个问题、Chrome 的子进程归到 Chrome、系统进程归系统，五种情况全部对（[U-ACC-2|fe1e]）。

第三期出命令行：有缓存时一条 `whoate top --json` 不到 0.3 秒返回（[U-ACC-3|41ff]）。现场验证两件事：在终端里起一个小网页服务再把那个终端关掉，一条命令能找回它来自哪个 pane（[U-ACC-4|ba7a]）；对这个会话本身跑一次，返回的会话名、标题和第一个问题与 Claude 自己记的一致（[U-ACC-5|d18b]）。

第四期出界面：菜单栏面板和主窗口浅色、深色各截一张，文字不溢出；每秒刷新时它自己平均 CPU 不到 1%；点「关闭」会先弹确认（[U-ACC-6|0f94]）。第五期发布：换一个干净的用户目录按说明一行命令装好能用，下载页有命令行和应用两个包，介绍页能打开（[U-ACC-7|8627]）。

## 6. 最可能翻车的假设

最大的假设是「没有 Xcode 也能把 Rust 核心接进 Mac 界面」，已经验证通过：今天在本机只用命令行工具编出了调用 Rust 的 SwiftUI 程序（[U-SPK-1|07fa]）。第二个是「读进程内存够快」，已验证：读 702 个进程用 4 毫秒，读不到的 202 个系统进程改用 `top` 每 6 秒补一次（[U-SPK-2|4f56]）。第三个是「孤儿进程还记得自己来自哪个终端」，已验证：抽查 10 个进程 9 个能读到（[U-SPK-3|4f53]）。

接受风险的有两条：opencode 和 kilo 的会话靠「同目录、启动时间相近」去配对，同一目录同时开好几个会话可能配错，界面会标「推断」（[U-SPK-4|2147]）；Claude 的会话文件是它的内部格式，哪天它改了，会话信息退化成只显示目录，进程归属不受影响（[U-SPK-5|c4ec]）。

需要 spike 的一条：界面每秒刷新时自己能不能把 CPU 压在 1% 以下，第四期第一步花一小时测，不达标改成 2 秒刷新（[U-SPK-6|8f90]）。
